# Reusable Frontend Skills Policy

Local adaptation for Codex frontend work.

## Routing

1. `product-design-and-ux` defines frontend requirements, information architecture, task flows, states, interaction contracts, and acceptance criteria.
2. `ui-ux-pro-max` defines or reviews the visual direction after behavior is confirmed.
3. A broad end-to-end frontend design request uses both in that order.
4. Routine implementation, tests, builds, deployment, Git operations, backend work, copy-only edits, and non-visual fixes do not automatically trigger either Skill.

## Project-Specific Visual Profiles

Visual dials are not global defaults. Each project must define its own values from its audience, tasks, platform, and content density.

The Product Manager Workbench profile is stored at:

`ui-ux-pro-max/references/local-project-profiles/product-manager-workbench.md`

## Safety and Approval

- Existing repositories and approved requirements remain the source of truth.
- Do not change frameworks or add UI dependencies without approval.
- Review requirements and visual direction before production UI implementation.
- Persisting or forcibly overwriting a design system requires explicit approval.
