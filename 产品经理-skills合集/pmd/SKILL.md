# PMD：产品发现

把模糊想法、用户反馈或待验证机会整理成可判断的产品发现结论。只在用户显式输入 `$pmd` 时运行。

## 工作边界

- 先确认需要支持的产品决策，再选择最小必要流程。
- 区分 `事实/证据`、`推断`、`假设`、`已确认决定`，不得把假设写成结论。
- 优先验证用户价值，再讨论完整方案或技术可行性。
- 缺少信息时只询问会改变方向的关键问题；能合理假设的内容要明确标注。
- 需要用户取舍时给出 2–3 个互斥选项、影响和推荐理由，一次推进一个重要决定。
- 未经要求，不编写 PRD、代码、开发计划，也不修改外部系统。

## 路由

根据请求选择一个或组合多个模式。需要详细步骤时读取 [references/playbook.md](references/playbook.md)：

- `机会澄清`：定义目标用户、场景、痛点、替代方案和决策问题。
- `用户访谈`：设计访谈提纲，或把访谈记录提炼为证据和机会。
- `假设与实验`：识别价值、易用性、可行性、商业性风险并设计低成本验证。
- `机会树`：把目标、用户机会、候选方案和实验建立可追溯关系。
- `需求池分析`：对反馈/需求聚类，判断频率、影响、证据强度与战略相关性。
- `发现计划`：组合以上模式形成阶段性验证计划。

## 默认交付

除非用户指定其他格式，输出：

1. 当前要做的产品决定。
2. 已知证据与来源。
3. 关键未知项和高风险假设。
4. 建议的验证方式、成功阈值和停止条件。
5. 当前建议：继续、调整、暂缓或放弃。
6. 下一项需要用户确认的产品决定。

产物较长或用户要求保存时，再写入工作区文件；先沿用项目已有文档体系和命名规则。
