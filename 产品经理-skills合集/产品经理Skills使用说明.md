# 产品经理 Skills 使用说明

这套合集包含三个彼此衔接、但不会自动触发的个人 Skills。

## 触发码

| 输入代码 | 名称 | 什么时候使用 |
|---|---|---|
| `$pmd` | 产品发现 | 还在判断用户问题、机会、需求真伪或验证方法时 |
| `$pms` | 产品战略 | 需要确定目标用户、定位、价值、取舍、商业模式或指标时 |
| `$pme` | 产品执行 | 产品方向已经确认，需要写 PRD、故事、验收、计划或测试材料时 |

必须带 `$`，并使用英文小写字母。普通聊天中只说“用户调研”“产品战略”或“写 PRD”不会自动启用这三个 Skills。

## 最简单的使用方法

在消息开头输入触发码，后面直接写任务：

```text
$pmd 帮我判断这个需求是不是真需求：用户想一次比较四个大模型的回答。
```

```text
$pms 根据现有调研，帮我确定桌面版产品经理工作台的首批目标用户和明确不做的方向。
```

```text
$pme 把已经确认的需求整理成 PRD，先标出待决定项，不要写代码。
```

可以同时附上文件、截图或路径。Skill 会优先使用你已经提供的内容，只询问会影响方向的关键缺口。

## 三个 Skill 如何衔接

```text
$pmd 发现和验证问题
   ↓ 用户确认机会值得做
$pms 确定定位、价值和取舍
   ↓ 用户确认战略方向
$pme 形成 PRD、故事、验收和交付材料
```

不要求每次都走完整流程：已有明确战略时可以直接用 `$pme`；只有一个模糊想法时应从 `pmd` 开始。

## 常用示例

### `$pmd`

```text
$pmd 给这批用户反馈做主题聚类，区分事实、推断和假设。
$pmd 为“多模型对比”设计一轮用户访谈，不要问诱导性问题。
$pmd 找出这个方案最危险的三个假设，并设计最低成本实验。
```

### `$pms`

```text
$pms 对比三个目标客户群，推荐首批服务对象，并说明放弃了什么。
$pms 把现有材料整理成一页产品战略，未知内容标成假设。
$pms 压力测试当前定位，找出竞争对手容易复制的部分。
```

### `$pme`

```text
$pme 根据确认内容更新现有 PRD，只修改受影响章节。
$pme 把这个功能拆成用户故事和可测试的验收标准。
$pme 为 M2 生成产品验收清单，区分自动测试和人工验收。
```

## 组合调用

一条消息可以指定顺序，但重大产品选择仍会暂停等待你确认：

```text
$pmd 先分析这批反馈；如果证据足够，再给出进入 $pms 的建议，但不要直接替我确认战略。
```

不建议在一条消息里要求三个 Skill 一口气完成所有工作，因为早期错误会一路传到 PRD 和开发计划中。

## 重要边界

- 三个 Skill 默认只做产品工作，不会因为生成了 PRD 就自动写代码、提交 Git 或部署。
- 如果你明确要求实施，AI负责技术实现、测试和修复；你负责产品选择、必要账号/密钥和最终验收。
- 输出会区分已确认、建议、假设、待决定和已验证，避免把计划写成完成状态。
- 第三方上游灵感来自 `phuryn/pm-skills`，本合集已经按你的中文工作方式和显式触发要求重新整理。

## 首次生效

创建后建议新建一个 Codex 对话，或完全退出并重新打开 Codex，再输入 `$pmd`、`$pms` 或 `$pme`。如果输入 `$` 后能在技能列表中看到对应名称，就说明已经加载成功。
